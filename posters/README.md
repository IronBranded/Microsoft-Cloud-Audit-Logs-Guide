# Posters

Generated by `scripts/build-posters.ps1` from `data/`. Do not edit these files by hand; change the catalog and rebuild.

| Poster | Answers | Files |
|---|---|---|
| 1. Microsoft Cloud Forensic Evidence Map | What evidence source to examine, whether it should exist, and when it is relevant | `poster-1-evidence-map/` |
| 2. Microsoft Cloud Forensic Evidence Acquisition, Sheet A | How PowerShell reaches each evidence source through Azure PowerShell and Azure Monitor: paths 1 (native cmdlets) and 3 (Azure Monitor and KQL) | `poster-2-powershell-acquisition/poster-2a-*` |
| 2. Microsoft Cloud Forensic Evidence Acquisition, Sheet B | Microsoft Graph, endpoints, and Microsoft 365: paths 2 (Microsoft Graph), 4 (Windows Eventing), 5 (Graph Security and Defender), and 6 (Microsoft 365 Audit) | `poster-2-powershell-acquisition/poster-2b-*` |

All three sheets are 48 x 36 in (landscape). The Poster 2 split is set in `data/presentation.json`; each sheet repeats the acquisition warning and legends so it can hang on its own. The PDFs keep every Microsoft Learn link clickable. The PNG files are half-scale previews.

Each edition shows the catalog entries whose `publication.poster_1` or `publication.poster_2` flag is set, which is currently every Core entry. Extended entries appear on the interactive site. Evidence planes with no verified entries yet are listed on Poster 1 under "Not yet catalogued" rather than filled with unverified content.

Poster 2 groups commands by the six acquisition paths in `data/presentation.json`. When several sources in a path share a permission, paging rule, or limitation, it is printed once in that path's shared box, and each affected card says so.

The sheets split by API family rather than by path number because that balances them: both sheets fill about 91% of their columns at 13.5 pt body text. `build-posters.ps1` prints how full each sheet is and warns above 95%, so adding entries shows early when the split needs revisiting.
