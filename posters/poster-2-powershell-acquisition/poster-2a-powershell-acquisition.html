Azure Activity Log

Acquisition method Az PowerShell
API Activity Log REST API (Azure Resource Manager) (GA)
PowerShell module or interface Az.Monitor, Az PowerShell (Activity Log REST API)
Cmdlet, API, or query mechanism
ACQUIREGet-AzActivityLogCurrentGet-AzActivityLog -StartTime ([datetime]"2026-10-01T00:00:00Z") -EndTime ([datetime]"2026-10-07T23:59:59Z") | ConvertTo-Json -Depth 10 | Out-File activity-log.json
Paging and limits: Microsoft's examples return at most 1,000 events per call; narrow the time range or set -MaxRecord. Both ends of the range must fall inside the 90-day retention window.
Parameter sets scope by subscription (default), -ResourceGroupName, -ResourceId, -ResourceProvider, or -CorrelationId; -Caller and -Status filter further; -DetailedOutput returns full properties. Microsoft's examples export with Export-Csv; JSON keeps nested claims and properties intact.
ACQUIREInvoke-AzRestMethodGAInvoke-AzRestMethod -Method GET -Path "/providers/Microsoft.Insights/eventtypes/management/values?api-version=2015-04-01&`$filter=eventTimestamp ge '2026-10-01T00:00:00Z' and eventTimestamp le '2026-10-07T23:59:59Z'"
Paging and limits: Verification required
Tenant-level events are separate from subscription events and can include management group or subscription creation.
ACQUIREInvoke-AzRestMethodPreviewInvoke-AzRestMethod -Method GET -Path "/providers/Microsoft.Management/managementGroups/<managementGroupId>/providers/Microsoft.Insights/eventtypes/management/values?api-version=2017-03-01-preview&`$filter=eventTimestamp ge '2026-10-01T00:00:00Z' and eventTimestamp le '2026-10-07T23:59:59Z'"
Paging and limits: Verification required
Microsoft documents the 2017-03-01-preview API version as required for management-group queries.
Required permissions
  • Azure RBAC: Monitoring Reader (can query the Activity Log). A custom role with Microsoft.Insights/eventtypes/* limits access to Activity Log reads.
Prior-collection requirement
AUTO EXPORT Automatic with limited native retention
Collected by default with no configuration.
Native retention: 90 days
Recommended output format JSON CSV
Important limitations
  • Retained for 90 days natively; both ends of a query time range must fall inside that window.
  • Does not typically capture read operations. Operations inside a resource are in Resource Logs.
  • Tenant- and management-group-level scopes only capture Azure Resource Manager events in those hierarchies.
  • Values in AzureActivity fields can differ in case; use case-insensitive operators.
  • Entries are usually available 3 to 20 minutes after the event.
  • The Activity Log REST API is limited to 50 queries per 30 seconds with a 75-second maximum timeout; querying AzureActivity in a workspace counts against the general Logs query limits instead.

14 Azure Monitor ! Conditional · 1 open gap

Diagnostic Settings

Acquisition method Az PowerShell
API Azure Resource Manager (Microsoft.Insights/diagnosticSettings) (Current)
PowerShell module or interface Az.Monitor
Cmdlet, API, or query mechanism
INSPECTGet-AzDiagnosticSettingCurrentGet-AzDiagnosticSetting -ResourceId <resourceId> | ConvertTo-Json -Depth 10
Returns the active (current) settings, not their history.
INSPECTGet-AzDiagnosticSettingCategoryCurrentGet-AzDiagnosticSettingCategory -ResourceId <resourceId>
CHANGES CONFIGNew-AzDiagnosticSettingCurrentNew-AzDiagnosticSetting -Name <name> -ResourceId <resourceId> -WorkspaceId <workspaceResourceId> -Log $log -Metric $metric
Changes the environment. Record who ran it and when. It does not create logs for activity that happened before it existed.
Required permissions
  • Azure RBAC: Monitoring Reader to view diagnostic settings; Monitoring Contributor to create or edit them, plus ListKeys on a storage account or Event Hubs destination. Read access to the resource type and scope is also needed.
  • Microsoft Entra role: Security Administrator (least privileged to configure Microsoft Entra diagnostic settings)
Prior-collection requirement
CONFIG Configuration required
A diagnostic setting names the categories (or a category group: allLogs, or audit for logs that record interactions with data or service settings) and up to one destination of each type: Log Analytics workspace, Azure Storage account, Event Hubs, or a partner solution.
Native retention: Not applicable (configuration object)
Recommended output format JSON
Important limitations
  • Shows current configuration only; on its own it does not prove what was configured at the time of an incident.
  • Some services need more than one diagnostic setting to collect both legacy and resource-specific logs (for example, Azure Firewall).
  • Switching an existing setting to resource-specific mode leaves earlier data in AzureDiagnostics.
  • Data starts flowing up to 90 minutes after a setting is created.
  • If a resource is deleted or renamed and later re-created with the same name, a leftover diagnostic setting can apply to the new resource and resume collection. Microsoft advises deleting diagnostic settings with the resource.
  • Diagnostic settings don't allow filtering within a category; transformations filter supported tables in the workspace.

Azure Monitor and KQL

Evidence already centralized in a Log Analytics workspace or Microsoft Sentinel. Check whether the source writes to AzureDiagnostics or a resource-specific table.

Shared by several sources in this path
Required permissions
  • Azure RBAC: Monitoring Reader (can search Log Analytics workspaces and run log queries)
Paging and limits
  • No paging; Azure Monitor log query limits apply.
  • No paging. Logs query API limits: 500,000 records and about 100 MB per query, 10-minute maximum run time (3-minute default), 200 requests per 30 seconds per user. Split large pulls by time range.
Important limitations
  • Monitoring Reader and Monitoring Contributor don't grant read access to log data in storage accounts or Event Hubs; reading an archived copy needs separate data access.

Replace the placeholder with the service's resource-specific table from the supported categories reference.
Required permissions
  • Plus the shared permissions for this path
Prior-collection requirement
CONFIG EXPORT Configuration required
Create a diagnostic setting for each resource and select the categories to collect.
Native retention: None: not collected or stored by Azure Monitor unless a diagnostic setting routes them
Recommended output format JSON CSV
Important limitations
  • Not completely lossless: store-and-forward with retries but no transactional guarantees, so small losses can occur.
  • Ingestion latency varies by destination and service.
  • AzureDiagnostics is not the universal table. Most services write to resource-specific tables, and some let you choose the mode.
  • Storage blobs are named by the time records were received, so a blob can contain records outside the hour in its path.
  • Data starts flowing up to 90 minutes after a diagnostic setting is created; nothing is collected for the period before it existed.

Virtual network flow logs

Acquisition method Azure Monitor and KQL
PowerShell module or interface Az.OperationalInsights
Cmdlet, API, or query mechanism
ACQUIREInvoke-AzOperationalInsightsQueryCurrentInvoke-AzOperationalInsightsQuery -WorkspaceId <workspace-id> -Query "NTANetAnalytics | where SubType == 'FlowLog'" -Timespan (New-TimeSpan -Days 7)
Paging and limits: see the shared box for this path.
Use only SubType FlowLog; other values are internal.
Required permissions
  • Azure RBAC: Verification required: Network Watcher and storage account permissions (Microsoft documents a Network Watcher RBAC permissions article) Verification required
Prior-collection requirement
CONFIG EXPORT Configuration required
Create a flow log on the virtual network, subnet, or network interface and choose a storage account.
Native retention: Set per flow log in days on Standard general-purpose v2 storage accounts; 0 keeps data until manually deleted
Recommended output format JSON CSV
Important limitations
  • The storage account must be in the same region as the virtual network and be Standard tier.
  • Rotating customer-managed keys on the storage account stops flow logging until it is disabled and re-enabled.
  • Don't modify flow-log blobs while they are being written; it can break writes for that hour's blob.
  • Traffic can't be recorded at a private endpoint; it is captured at the source VM.
  • Outbound VM flows to ExpressRoute aren't recorded when flow logging is enabled on the ExpressRoute gateway subnet; FastPath traffic bypasses the gateway.
  • Azure Container Instances aren't supported.

Record every acquisition

  • Source system and scope: tenant, subscription, workspace, resource, or device
  • Query or filter used, including the time range
  • UTC acquisition start and end time
  • Collecting account or application identity, and its permission context
  • Tool, module, or API name and version
  • Original output format and any export format
  • How pagination and result limits were handled
  • Errors, throttling, and retries
  • Known completeness limitations
  • Hash of every file produced (for example, SHA-256)

Preserve structured raw results before creating summaries. An export mechanism does not establish legal chain of custody by itself.
