Microsoft Graph PowerShell for Microsoft Entra activity logs and other Graph resources.

01 Entra ID ✓ Verified

Audit logs

Acquisition method Microsoft Graph PowerShell
API Microsoft Graph (audit logs API) (GA)
PowerShell module or interface Microsoft Graph PowerShell, Microsoft.Graph.Reports
Cmdlet, API, or query mechanism
CONNECTConnect-MgGraphCurrentConnect-MgGraph -Scopes "AuditLog.Read.All","Directory.Read.All"
Add Policy.Read.ConditionalAccess when Conditional Access details are needed.
ACQUIREGet-MgAuditLogDirectoryAuditGAGet-MgAuditLogDirectoryAudit -Filter "activityDateTime ge 2026-10-01T00:00:00Z and activityDateTime le 2026-10-07T23:59:59Z" -All
Paging and limits: -All follows every page; -Top and -PageSize bound the result. activityDateTime supports eq, ge, and le in $filter, and $orderby.
Other documented filters: activityDisplayName (eq, startswith), correlationId (eq), loggedByService (eq), initiatedBy/user/id, initiatedBy/user/userPrincipalName, and initiatedBy/app/appId.
Required permissions
  • Microsoft Graph (application): AuditLog.Read.All (least privileged); Directory.Read.All (higher privileged)
  • Microsoft Graph (delegated): AuditLog.Read.All (least privileged); Directory.Read.All (higher privileged)
  • Microsoft Entra role: Reports Reader (least privileged), Security Reader, or Security Administrator to read audit logs
  • Microsoft Entra role: Attribute Log Reader or Attribute Log Administrator for custom security attribute audit logs
  • Microsoft Entra role: Security Administrator (least privileged to configure Microsoft Entra diagnostic settings)
Prior-collection requirement
AUTO LICENSE EXPORT Automatic with limited native retention
Generated without configuration.
Native retention: 7 days (Microsoft Entra ID Free); 30 days (Microsoft Entra ID P1 or P2)
Recommended output format JSON CSV
Important limitations
  • Native retention is 7 or 30 days. Without a diagnostic setting in place before the incident, older records cannot be recovered.
  • Custom security attribute audit logs and provisioning logs are only on the Microsoft Graph beta endpoint.
  • Audit logs are available only for features the tenant has licensed.
  • The IP address in an audit record is the OAuth client's IP address (the TCP peer of the service endpoint), not necessarily the end user's device.

Sign-in logs

Acquisition method Microsoft Graph PowerShell
API Microsoft Graph (GA)
PowerShell module or interface Microsoft Graph PowerShell, Microsoft.Graph.Reports, Microsoft.Graph.Beta.Reports
Cmdlet, API, or query mechanism
CONNECTConnect-MgGraphCurrentConnect-MgGraph -Scopes "AuditLog.Read.All","Directory.Read.All"

ACQUIREGet-MgAuditLogSignInGAGet-MgAuditLogSignIn -Filter "createdDateTime ge 2026-10-01T00:00:00Z and createdDateTime le 2026-10-07T23:59:59Z"
Paging and limits: Maximum and default page size is 1,000; most recent first. Filter on a time range to avoid timeouts.
The v1.0 API returns interactive user sign-ins (and successful federated sign-ins) only.
ACQUIREGet-MgBetaAuditLogSignInBetaGet-MgBetaAuditLogSignIn -Filter "(createdDateTime ge 2026-10-01T00:00:00Z and createdDateTime le 2026-10-07T23:59:59Z) and signInEventTypes/any(t: t eq 'nonInteractiveUser')"
Paging and limits: Verification required
Beta APIs are subject to change and aren't supported for production. Without an event-type filter the API returns interactive user sign-ins only.
Required permissions
  • Microsoft Graph (application): AuditLog.Read.All (least privileged); add Directory.Read.All to avoid intermittent license-check errors
  • Microsoft Graph (application): Policy.Read.ConditionalAccess (or Policy.Read.All) to receive appliedConditionalAccessPolicies
  • Microsoft Entra role: Global Reader, Reports Reader, Security Administrator, Security Operator, or Security Reader (delegated access)
Prior-collection requirement
AUTO LICENSE EXPORT Automatic with limited native retention
Generated without configuration.
Native retention: 7 days (Microsoft Entra ID Free); 30 days (Microsoft Entra ID P1 or P2)
Recommended output format JSON CSV
Important limitations
  • Without a signInEventTypes filter, the List signIns API returns only interactive user sign-ins; the other three types require the beta endpoint.
  • Only sign-ins within the Microsoft Entra default retention period are available through the API.
  • appliedConditionalAccessPolicies is omitted when the caller cannot read Conditional Access data.
  • Each sign-in type is a separate diagnostic-setting category; routing only SignInLogs leaves the other three types uncollected.

CONFIG POLICY EXPORT Auditing policy dependent

  • Invocation logging (start and stop events) produces a high volume of events.
  • The PowerShell 7 channel exists only after its event provider is registered.

Microsoft Graph Security and Defender interfaces

Defender XDR incidents and alerts and advanced hunting through the Microsoft Graph security API.

08 Defender for Endpoint ✓ Verified

Advanced hunting device tables (endpoint telemetry)

Acquisition method Microsoft Graph Security API
API Microsoft Graph security API (runHuntingQuery) (GA)
PowerShell module or interface Microsoft Graph PowerShell, Microsoft.Graph.Security
Cmdlet, API, or query mechanism
CONNECTConnect-MgGraphCurrentConnect-MgGraph -Scopes "ThreatHunting.Read.All"
ACQUIREStart-MgSecurityHuntingQueryGAStart-MgSecurityHuntingQuery -Query "DeviceProcessEvents | where InitiatingProcessFileName =~ 'powershell.exe' | where ProcessCommandLine contains 'appdata' | project Timestamp, FileName, InitiatingProcessFileName, DeviceId | limit 2" -Timespan "P30D"
Paging and limits: No paging. Up to 100,000 rows and 50 MB per result; requests over 3 minutes time out; HTTP 429 when the tenant quota is reached.
Timespan defaults to 30 days. If both the query and Timespan set a time filter, the shorter span applies.
Required permissions
  • Microsoft Graph (application): ThreatHunting.Read.All
  • Microsoft Graph (delegated): ThreatHunting.Read.All
Prior-collection requirement
DEPLOY LICENSE EXPORT Deployment dependent
Devices must be onboarded to Defender for Endpoint.
Native retention: Advanced hunting returns data from the past 30 days
Recommended output format JSON CSV
Important limitations
  • 30-day lookback in advanced hunting.
  • Per-query limits: 100,000 rows and 50 MB; 3-minute time-out; tenant CPU quotas.
  • Advanced hunting data is in UTC.
  • Data stored only in the Microsoft Sentinel data lake isn't available in advanced hunting.
  • Only signals from onboarded devices exist.
  • Defender for Endpoint detection is not an auditing or logging solution that records every operation; the sensor throttles high rates of repeated identical events.
  • Behavioral telemetry is stored for six months; advanced hunting queries cover 30 days.

Microsoft 365 Audit interfaces

Bounded interactive searches (Search-UnifiedAuditLog), asynchronous Graph audit searches, and the Management Activity API feed for programmatic download.

10 Purview Audit ! Conditional · 1 open gap

Unified audit log

Acquisition method Exchange Online PowerShell
API Office 365 Management Activity API (Microsoft's recommendation for programmatic download); Microsoft Graph Audit Search API (GA)
PowerShell module or interface ExchangeOnlineManagement, Exchange Online PowerShell, Microsoft.Graph.Security, Office 365 Management Activity API
Cmdlet, API, or query mechanism
CONNECTConnect-ExchangeOnlineCurrentConnect-ExchangeOnline -UserPrincipalName <admin-upn>
Install or update the module with Install-Module/Update-Module -Name ExchangeOnlineManagement. Connect-IPPSSession connects to Security & Compliance PowerShell instead.
ACQUIRESearch-UnifiedAuditLogCurrent$sid = [guid]::NewGuid().ToString(); Search-UnifiedAuditLog -StartDate 2026-10-01 -EndDate 2026-10-07 -SessionId $sid -SessionCommand ReturnLargeSet -ResultSize 5000
Paging and limits: Default returns up to 100 records. ReturnLargeSet: unsorted, up to 50,000 results per search, 5,000 per page. ReturnNextPreviewPage: sorted, up to 5,000. Don't mix SessionCommand values within one SessionId. Split larger searches.
Filters include -UserIds, -Operations, -RecordType, -IPAddresses, -ObjectIds, -SiteIds, and -FreeText. ReturnLargeSet output can contain duplicates; de-duplicate and sort afterwards.
ACQUIRENew-MgSecurityAuditLogQueryGA$q = New-MgSecurityAuditLogQuery -DisplayName "<case-id> audit search" -FilterStartDateTime ([datetime]"2026-10-01T00:00:00Z") -FilterEndDateTime ([datetime]"2026-10-07T23:59:59Z") -RecordTypeFilters "exchangeItem"
The query runs asynchronously; its status moves through notStarted, running, and succeeded (or failed or cancelled). Other filters: operations, user principal names, IP addresses, object IDs, administrative units, keyword, and service. Tenant-level daily submission and concurrent-query limits apply.
ACQUIREGet-MgSecurityAuditLogQueryRecordGAGet-MgSecurityAuditLogQueryRecord -AuditLogQueryId $q.Id
Paging and limits: Verification required
Records include createdDateTime, auditLogRecordType, operation, userPrincipalName, clientIp, objectId, service, and the workload-specific auditData object.
ACQUIREInvoke-WebRequestCurrentInvoke-WebRequest -Method GET -Headers $headerParams -Uri "https://manage.office.com/api/v1.0/<tenant-id>/activity/feed/subscriptions/content?contentType=Audit.SharePoint&startTime=2026-10-01T00:00&endTime=2026-10-01T23:59&PublisherIdentifier=<tenant-id>"
Paging and limits: Results are truncated when large; follow the NextPageUri response header until it is absent. startTime and endTime must both be set (or both omitted), be no more than 24 hours apart, and start no more than 7 days in the past.
$headerParams holds a Microsoft Entra access token with the ActivityFeed.Read permission. A subscription to the content type must already exist (/subscriptions/start); the first content can take up to 12 hours to appear. Include PublisherIdentifier on every call, including content downloads, to avoid shared throttling.
Required permissions
  • Exchange Online / Purview role: View-Only Audit Logs or Audit Logs
  • Microsoft Graph (application): Audit Search API: a workload-scoped permission (AuditLogsQuery-Entra.Read.All, -Exchange.Read.All, -SharePoint.Read.All, -OneDrive.Read.All, -CRM.Read.All, -Endpoint.Read.All) or AuditLogsQuery.Read.All; the same permissions apply to delegated access
  • Office 365 Management Activity API: ActivityFeed.Read (Read activity data for an organization); DLP sensitive data needs the separate Read DLP sensitive data permission
Prior-collection requirement
AUTO LICENSE POLICY EXPORT Automatic
Audit (Standard) is enabled by default for most organizations, but unified audit log ingestion can be turned off (Set-AdminAuditLogConfig -UnifiedAuditLogIngestionEnabled $false).
Native retention: 180 days (Audit Standard); 1 year by default for Microsoft Entra ID, Exchange, OneDrive, and SharePoint records of Audit (Premium) users
Recommended output format JSON CSV
Important limitations
  • Microsoft recommends the Office 365 Management Activity API, not Search-UnifiedAuditLog scripts, for programmatically downloading audit data.
  • Search-UnifiedAuditLog returns 100 records by default; ReturnLargeSet results are unsorted and can contain duplicates.
  • Mailbox audit events for some users may not appear in searches even with mailbox auditing on by default.
  • Search-UnifiedAuditLog returns no results in Office 365 operated by 21Vianet.
  • Retention depends on the license of the user who performed the activity.
  • The Management Activity API is a feed, not a historical search: content can be listed only for the last 7 days, events within a blob aren't in occurrence order, and nothing is available for a content type until a subscription exists.
  • If unified audit logging is off, the Management Activity API returns an error rather than data.

Record every acquisition

  • Source system and scope: tenant, subscription, workspace, resource, or device
  • Query or filter used, including the time range
  • UTC acquisition start and end time
  • Collecting account or application identity, and its permission context
  • Tool, module, or API name and version
  • Original output format and any export format
  • How pagination and result limits were handled
  • Errors, throttling, and retries
  • Known completeness limitations
  • Hash of every file produced (for example, SHA-256)

Preserve structured raw results before creating summaries. An export mechanism does not establish legal chain of custody by itself.
